**Versions:** PlusEMU v2026.10.07-3122f10, Volt 3.5.0 build 2429065 (then still named "Octane client"), hotel files 1.0.0. Volt Renderer had merged work but no release yet.

This week ends with the first public release of PlusEMU, Volt and the hotel files. The work before these changes, the fork from PlusEMU and Octane, is described on [Before the first release](/changelog/before-release/).

## Highlights
- **First public release.** PlusEMU ships ready-to-run builds for Linux and Windows, with a SQL file for a fresh database. The client and the hotel files are published for the installers.
- **Modern WIRED.** New triggers, effects, conditions, selectors, add-ons and variables, with editors that match the client.
- **Secure login, roles and permissions.** The emulator serves login itself with safe password hashing. Staff ranks are replaced by roles with permissions, managed in the client.
- **Habbo Club as a real membership.** Players buy HC in the shop, and the server checks it for clothes, room models, chat bubbles and more.
- **Trusted camera.** The hotel renders room photos itself, so players cannot upload their own images.
- **SnowStorm** is back, using the official AIR game protocol.

## PlusEMU v2026.10.07-3122f10

### Getting started
- PlusEMU now runs on .NET 10.
- Each release has self-contained Linux and Windows builds, so the server does not need .NET installed. The emulator can also run as a Windows service.
- A fresh-install SQL file builds a new database in one step.
- Server setting values keep their original upper and lower case, so asset URLs and tokens work. Missing server name and host settings get default values.
- Logging out at the old online-time limit no longer stops the hotel.

### Login, roles and staff tools
- The emulator serves the login API at `/api/auth/*`. Passwords use Argon2id hashing. Login tickets work once, sessions are per device and can be revoked, and login attempts are rate limited.
- A CMS can handle accounts instead. Set `AuthApi.Enabled` to `false` and the CMS gives out the game login ticket. RCON commands in JSON now confirm if they worked.
- A client that reconnects gets a fresh login ticket. A refused login gets an answer instead of a hanging client.
- Ranks are replaced by roles with permissions. A user can have several roles, a role can expire, and single permissions can be granted or denied per user. All changes go to an audit log.
- New chat commands `:giverole` and the matching revoke command assign and remove roles, also for offline users.
- The in-client housekeeping panel works, with rights per action and an audit log. A ban, reset or demotion signs the account out everywhere.
- The in-client catalog editor and furni editor work, with undo, live catalog reloads and permission checks.

### Habbo Club and catalog
- Habbo Club is now a real paid membership, with VIP merged into it. The server checks it for clothes, room models, chat bubbles, dances, groups and room settings. Members get monthly gifts and payday. Staff get the perks through the `club.access` permission.
- The HC page lists the 1, 3 and 6 month offers, and buying one extends the membership.
- The server sends each user the chat bubbles and room models they may use.
- The catalog supports the official Habbo structure: deeper page trees, per-offer club level and order, and front page items.
- The catalog is stored in proper tables for offers, products and pages. Limited edition stock is now enforced. Back up your database before this update.
- WIRED offers found through search load again. Gifts with an attached badge are refused before the buyer pays. Group purchases charge credits only after the group is made.

### WIRED
- Modern WIRED boxes: new triggers, effects, conditions, selectors, add-ons and variables. Existing WIRED settings keep working.
- New WIRED boxes are on the Recently Added catalogue page.
- WIRED editors open on freshly placed furni, and the older editor forms show correctly.
- A WIRED box loses its settings when you pick it up, also with `:pickall`.
- Delayed effects run per user, so two users who fire the same stack each get their own effect.
- `:wired` shows the room log and the WIRED monitor. Monitor usage counts every run, not only the busiest one.
- Moved furni is blocked by any furniture, unless Movement Physics allows moving through it. A line of furni moves together, and a stack on one tile moves as one unit.
- Move and Rotate diagonals and repeater timers work like on AIR. Editor choices are kept when you save.
- Triggers that use furni from a selector fire again. Bots and pets can fire walk on and walk off triggers.
- Condition evaluation add-ons and signal receivers work like on Habbo.
- A box saved while it flashed now flashes again after a room reload.

### Rooms, furni and walking
- The floor plan editor uses the packets of the current Habbo editor. Saves are safe, and users in the room are put back after the room rebuilds.
- Walk Magic Tiles are new. The stack height of Stack Magic Tiles is checked, limited to 0-40 and saved.
- A new walking engine (v2) is available with `pathfinding.engine=v2`. The original engine stays the default.
- With v2, rollers move in chains like on Habbo, gates open and close in order, a blocked route walks up to the blockage, quick back and forth clicks work, and you can step onto WIRED conveyors.
- With v2, `pathfinding.layering_enabled` lets avatars walk under raised furni and over bridges.
- Clicking a far vending machine, teleporter or hopper uses it when you arrive. Set `pathfinding.approach_auto_interact` to `0` to turn this off.
- The old walking engine no longer crosses blocked tiles or sealed corners.
- Furni placement reserves the item, so two actions cannot use the same furni.

### Camera
- The hotel renders photos itself on a private renderer. Players cannot send their own images or links.
- Photos match what players see: floors, walls, door, bots, pets, wall photos and moodlights.
- The renderer restarts by itself when its browser stops. The toolbar camera shows for users who may use it (`camera.enabled` and the `camera.use` permission).

### Games and new features
- SnowStorm, with the official AIR game protocol, lobby, matchmaking, arenas and leaderboards. Players vote for the arena in the lobby.
- Optional ray guns in SnowStorm, turned on with `gamecenter.snowwar.raygun.enabled`.
- Ice Tag poles work on ice fields.
- Jukeboxes and sound machines play discs and keep playlists.
- The recycler, Ecotron boxes and crafting altars work once you set up the prizes and recipes.
- Room surveys and word quizzes. Room owners start a quiz with `:wordquiz`.
- Group forums with moderation and read markers.
- Campaign calendars, the introduction reward track, talent tracks and the safety and Habbo Way quizzes work. Each reward is paid once.
- Habbicons can be bought, earned and used in rooms and private messages.
- Badge rarity scales with the number of active players, and the badge leaderboard works.
- The marketplace checks if furni can be sold. Set `catalog.marketplace.only_rare_ltd` to `1` to allow only rare and limited edition furni.

### Pets, groups and other fixes
- Pet purchases, placement and pickup are saved properly. Gnome boxes open after placing and after a reload.
- Group management works: settings, member rights, requests, kicks and deleting a group.
- Gift wrapping uses the chosen box and ribbon.
- Staff can test busy rooms with `:stress bots <amount>` and remove them with `:stress bots clear`.
- Custom name plates, borders, nick icons, chat colours and rank prefixes are removed. Packets use the official layouts again.
- Database updates now also work with mixed database collations.

## Volt and Volt Renderer

### New
- The login and sign-up screens follow the AIR login flow, over the hotel view. Login tokens stay in memory only.
- The client can use a login ticket from a CMS. With `auth.enabled=false` it hides login, account, housekeeping and catalog admin screens. A failed CMS session links back to the hotel website.
- Reconnects get a fresh login ticket instead of hanging. The Habbo loading screen shows right away, and the client logs in while game data loads.
- The client reads official Habbo `.hab` asset bundles. `asset.bundle.format` picks `hab` (default) or `nitro`.
- SnowStorm uses the official AIR game windows, with arena voting, in-game chat and ray guns.
- Housekeeping has a Roles tab for roles, permissions, members, overrides and the audit log. Staff tools use Habbo windows and ask before destructive actions. Staff features follow the server permissions.
- The floor plan editor, introduction reward track, Stack and Walk Magic tile widget and Habbo Club page match AIR.
- Badge rarity tiers show in the WIN63 order.

### Camera
- The camera uses only photos made by the hotel.
- New photos show in the roll right away, and you can open them before the hotel image arrives.
- The wall photo viewer matches AIR.
- Photos work at any window size, and wall photos load from the hotel website.

### Look and feel
- Windows, buttons, the toolbar, menus and the Me menu use the official Habbo skins.
- Avatar menus look the same for you and other users, stay above chat, and show owner rights controls again.
- `:wired` opens the WIRED creator tools. Log filters, child windows and selection marks work correctly.
- Direction editors show AIR's eight arrows. Area and placeholder name editors match Habbo.
- 586 missing UI text keys are added, so windows no longer show raw keys. Hotels can now translate them.
- Busy room chat stays smooth. Pets show as small portraits in chat bubbles, and command suggestions sit above the chat input again.
- Catalog tabs, navigator user counts and catalog quantities look like on Habbo. Temporary catalog previews no longer open an infostand.
- New groups show below the purse right away. Avatars stay visible while you place a pet, and pet placement cannot replace another avatar or bot.
- Saved avatar colours show when you open the editor again.

### Removed
- Builders Club, the fortune wheel, mentions, the emoji picker, the soundboard and custom name plates.
